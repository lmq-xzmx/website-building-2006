# 内容模版 —— 模版定结构，实例填内容，生成前台页面

> 2026-11-11 实现。这是「模版概念」的落地：
> **模版**定义一类内容的结构，**实例**按结构填内容，实例可以**生成前台页面**。

## 一、为什么要有这一层

模块模型解决了「页面由什么组成」（页面 → 模块 → 条目），但没回答「**一类内容长什么样**」：

- 案例该有客户、挑战、方案、量化结果
- 产品该有定位、能力说明、核心规格、亮点
- 文章该有导语、正文、要点

这些结构此前只存在于 `content/site.ts` 的写死字段里 —— 那是**人写、机器不碰**的内容包。
后果：后台没法对「一类内容」做增删改查，更没法按结构生成新页面。

模版层把「结构」独立出来，成为机器可写的一层。

## 二、三层的关系

```
模版 Template   字段 schema + 页面布局（怎么渲染成前台页面）
  ↓ 实例 Instance   按 schema 填的一份内容（可发布、可生成页面）
    ↓ 生成 Page   展开成页面 → 进编排 → 物化 → 上线
```

**与组件（片段）的分工**：

| | 组件（片段） | 模版实例 |
|---|---|---|
| 是什么 | **一段**可复用的内容 | **一类**内容的结构 |
| 复用方式 | 多个页面引用同一份 | 每个实例是独立的一份 |
| 改一处 | 所有引用点跟着变 | 只影响这一个实例 |
| 生成页面 | 不能（它是内容，不是结构） | 能 |

## 三、数据模型

| 位置 | 内容 |
|------|------|
| `sites/<id>/templates.json` | 模版库：`templates[]`（结构）+ `instances[]`（内容） |

### 模版字段类型

`text` 单行 / `longtext` 长文本 / `richtext` 富文本 / `image` 图片 /
`metrics` 指标组（value+unit+label）/ `list` 要点列表

### 页面布局块（block）

| 块 | 展开成 | 用哪个字段 |
|----|--------|------------|
| `heading` | hero 模块（H1 = 实例名） | 自动取第一个文本字段 |
| `text` | rich-text 模块 | 指定字段 |
| `metrics` | stats 模块 | 指定字段 |
| `bullets` | rich-text 模块（要点列表） | 指定字段 |
| `cta` | cta 模块（指向联系页） | — |

## 四、实例 → 页面

物化时，**已发布**的实例按模版布局展开成 PageDef：

- 页面路径 = `pathPrefix` + `/` + `slug`
- 页面带 `generatedFrom` = 实例 id —— **实例是唯一事实源**
- 重新生成是**更新**同一页，不是新建
- 实例下线（草稿/删除）→ 生成的页面自动摘除
- 只有标题和 CTA、没有实质内容块 → **不生成**（发布空壳比不发布更糟）

生成的页面走既有的 catch-all 路由 —— **骨架模板零改动**。

## 五、发布链路

```
改实例（后台「模版」标签页）
  → 保存实例（落 templates.json）
  → 点「生成前台页面」（写进编排，带 generatedFrom）
  → 发布台「发布并重建」（物化 + next build）
  → 前台页面出现
```

发布接口在物化前会自动再跑一次生成 —— 防止「改了实例但忘了生成」。

## 六、API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/sites/:id/templates` | 读模版 + 实例 |
| POST | `/api/sites/:id/templates` | 新建模版 |
| PUT | `/api/sites/:id/templates/:tid` | 改模版 |
| DELETE | `/api/sites/:id/templates/:tid` | 删模版（有实例引用时拒绝，409） |
| POST | `/api/sites/:id/template-instances` | 新建实例 |
| PUT | `/api/sites/:id/template-instances/:iid` | 改实例（已发布实例会校验必填） |
| DELETE | `/api/sites/:id/template-instances/:iid` | 删实例（连生成页一起摘） |
| POST | `/api/sites/:id/template-instances/:iid/generate` | 立即生成页面进编排 |

## 七、后台界面

「模版」标签页（左栏 + 右栏）：

- **左栏**：模版与其实例的树。模版行右侧有「+」直接建实例；实例行显示发布状态与是否已生成页面
- **右栏 · 模版详情**：字段结构清单 + 实例列表 + 新建实例
- **右栏 · 实例编辑器**：按模版字段逐个渲染控件（指标组是三列可增删的行编辑器），
  顶部有「生成前台页面 / 重新生成页面」「删除实例」，底部「保存实例」

字段控件按类型分：`text` 单行、`longtext` 多行（空行分段）、`list` 一行一条、
`metrics` 数值+单位+指标名的可增删行编辑器。

## 八、demo-saas 的三套模版与五个实例

| 模版 | 结构 | 实例 | 生成路径 |
|------|------|------|---------|
| 案例模版 | 客户名 → 挑战 → 方案 → 量化结果 | 股份制银行月度报表交付提速 | `/stories/joint-stock-bank` |
| | | 汽车 Tier 1 供应商数据打通 | `/stories/auto-tier1` |
| | | 股份制银行核心系统数据中台 | `/stories/bank-core` |
| 产品模版 | 定位 → 能力说明 → 核心规格 → 亮点 | 数据集成网关 | `/products/data-gateway` |
| 文章模版 | 导语 → 正文 → 要点 | 私有化部署的 12 项合规检查清单 | `/notes/pd-checklist` |

三个案例的内容**全部取自真实来源**：两个来自 `content/site.ts`（人写层），
一个来自片段库「客户案例」—— 也就是说原先散在三处的案例，现在都在后台可管了。

## 九、已知限制

- 富文本字段（`richtext`）目前按单行文本处理 —— 完整富文本编辑器待接
- 图片字段（`image`）目前按单行文本处理 —— 媒体库选择器待接
- 实例不支持多语言版本
- 模版的字段结构变更不影响已填的实例值（改字段名会让该字段的旧值失联）

## 十、网址与预览

「模版和实例都需要提供网址及预览」—— 实例的网址就是它生成的那个页面：

| 位置 | 给什么 |
|------|--------|
| 模版详情 | 结构预览（按布局块画骨架）+ 生成路径前缀（`<前缀>/<slug>`） |
| 实例编辑器 | 实例页面的网址（可复制）+ 内容预览（按当前填的内容渲染） |

**实例预览用编排里的生成页**（草稿态）—— 所以还没生成、还没发布的实例
也能看到自己长什么样；草稿还没进编排时，用草稿临时拼一个页面出来预览。

网址的域名随环境变：开发机是 `/preview/<siteId>/…`，生产机由
`SITE_BASE_URL` 换成正式域名 —— 一律走 `store.pageUrl()` 统一算，
不在界面里硬编码前缀。

站点的**全部**地址（不只是模版实例生成的）在顶栏「页面清单」里 ——
见 `docs/11-后台界面重构说明.md` 第六节。
