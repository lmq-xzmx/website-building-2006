# 11 · 后台界面重构说明（v3 打样台）

> 旧界面整目录归档在 `old-skin/`（含 v2 中间态 `old-skin/v2-current/`），已加入 `.gitignore`，仅作参考。

## 一、旧版问题诊断

对 `old-skin/` 七个面板（ui / editor / modules-ui / wechat-ui / media-ui / fragments-ui / history-ui，约 4700 行 TS 模板字符串）的体检结论：

**信息架构**
- 七个面板各自为政，没有统一的站点/工作区上下文，切换面板要重新理解一次"我在改哪个站"。
- 内容、素材、组件、版本之间的引用关系（条目→图片、模块→片段）完全不可见，全靠记忆。

**业务流程**
- 「编辑 → 校验 → 保存 → 构建 → 发布」五个动作散落在不同面板，没有一条主线路径；校验结果与编辑现场脱节。
- 发布与历史版本分开两个面板，回滚要跨页跳转。

**交互与代码**
- 全部 HTML/CSS/JS 塞在 TS 模板字符串里：客户端代码不能写反引号、无语法高亮、改一行要重启；七个面板互相 import，样式互相覆盖（选择器污染）。
- 大量 `alert()/confirm()/prompt()` 原生弹窗（20+ 处），中断操作流。
- 零组件复用：表单、列表、按钮每处手写一遍；`innerHTML` 拼接 100+ 处，XSS 面大。
- 无命令面板、无键盘快捷键、无脏状态提示——误关页面即丢稿。
- 无响应式设计，无空状态/加载态文案。

## 二、新前端设计

### 设计主张（token 系统）
- **主题**：「打样台」——印刷车间的工人台面。暖纸底（`--paper #F4F0E4`）、油墨黑（`--ink #191813`）、批注朱红（`--stamp #B4552F`），细规则线（`--rule`）代替卡片阴影，等宽字体标注路径与状态（像校对稿上的排字记号）。
- **字体**：正文系统衬线/无衬线双轨；路径、kbd、计数一律 `--font-mono`，制造"校样"质感。
- **版式**：左侧竖排导航（writing-mode 竖排，像书脊）+ 顶部工作条 + 主体作业区；行宽受限，标签句式大小写。

### 信息架构：七个作业区一条主线
```
概览(看板) → 内容(页面·模块·条目) → 素材(图片) → 组件(片段)
    → 分发(公众号) → 发布(校验·构建·版本) → 外观(版式与色板)
```
- 全局上下文常驻：顶部显示当前站点 + 脏状态（"有改动还没写进 modules.json —— ⌘S 保存"）。
- 跨区引用可见：内容区条目直接预览图片缩略；发布区问题点击跳回对应作业区。

### 交互升级
- **⌘K 命令面板**：跳页面、切作业区、执行动作（保存编排/重新校验/刷新知识库）。
- **⌘S 保存**，脏状态实时提示，离开页面拦截。
- 所有原生弹窗替换为内联确认/toast；统一空态与加载态文案。
- 模块与条目支持**拖拽排序**；富文本编辑器重写（块级模型，所见即所得）。
- 内容区第三栏内置**设备宽度实时预览**（iframe 物化页面）。

### 工程结构
```
apps/admin/public/console/
├── index.css        # 设计 token + 全部样式（无框架）
├── app.js           # 外壳：导航、顶部工作条、路由挂载
├── lib/             # dom / api / store / router / rich / preview / drag / picker / fixes
└── views/           # overview / content / media / components / wechat / release / appearance
```
- 客户端为原生 ES 模块，零构建、零依赖；`h()` 建 DOM，杜绝 innerHTML 拼接。
- 服务端 `ui.ts` 缩成薄壳：只注入登录用户与权限，界面全部静态资源化，新增 `/console/*` 静态路由。
- 旧面板文件（editor/modules-ui/wechat-ui/media-ui/fragments-ui/history-ui.ts）已删除，归档保留在 `old-skin/v2-current/`。

## 三、发布引导与审核闭环（v3.1）

重构后发现两处真实链路断点，一并补齐：

**问题**：发布台只把校验问题列出来，不告诉用户「导入后该怎么处理」；待办里的「待审」点进去跳到发布台，绕回原地 —— 前端根本没有审核控件，服务端 `/modules/review` 接口无人调用。

**做法：把「问题 → 动作」统一成一条闭环**（`lib/fixes.js`）

- `classify()` 按校验 `code`/文案把问题分成四类：**审核 / 重新提交 / 可一键修 / 需手改**，每类给出 `short`（标题）、`how`（怎么改）、`cta`（按钮文案）。
- 发布台不再是问题清单，而是**待办清单**：每行写清「改哪里、怎么改」，右侧直接给动作按钮：
  - 待审核 → 「通过审核」（调 `/modules/review` 写盘 → 自动重新校验）
  - 数据条缺数值 / FAQ 少了问号等 → 「补个问号」类一键修，或「去改数值」跳内容区并高亮对应字段
  - 知识库引用的条目，引导里明确写「改这里不会动原文」，消除「导入后能不能改」的疑惑
- 内容区顶部新增**修复提示条**（`fixbar`）：从发布台跳过来时，说明这条为什么挡发布、要改哪个字段，并把字段标出来。
- 概览「待审」改为跳到具体条目，不再绕发布台；审核状态控件移到条目头部（通过 / 提交审核 / 驳回），权限不足时按钮降级为「看内容」。
- 审核通过后若冒出新的字段问题，发布台文案明确解释「审核通过后，会接着检查这条的字段」，避免用户以为修了反而变多。

**冷启动防假阳性**：`store.check` 增加 `checking / ready / kbDown` 三态。校样没跑完或知识库断连时，发布台、顶栏、概览统一显示「正在校样…」，发布按钮禁用 —— 不再出现「0 问题、可以发布」的误导。

## 四、发布结果：网络地址与本地预览（v3.2–v3.3）

**问题**：发布完成面板首屏给的是「物化产物：`sites/xxx/content/modules.generated.ts`」—— 一个本地文件夹路径。用户要的是「发布完能打开站点」。

**做法：地址成为发布结果的主信息，路径退到技术细节**

- `resultPanel()` 重构：
  - 主区域为「站点已经更新 + 打开站点」主色按钮（网络地址）+ 复制链接；
  - 「站点域名」常驻一行，可点击、可复制，并标注来源；
  - `页面 / 版本 / 重建` 摘要保留；**物化产物路径与构建输出收进折叠的「技术细节」**，只在排错时看；
  - 重建失败时不隐藏地址（否则用户更没得点），改为「打开本地预览」次要按钮 + 明确说明「本地预览还是上一版，站点域名由部署流水线更新」。

**站点域名按环境解析（v3.3）**

- 早期把 `content/site.ts` 的 `url` 当成「正式域名」展示，那是内容包给搜索引擎看的 canonical，**不是后台访问地址**，开发机上显示 `https://www.yunshu-tech.com/` 是错的。
- `config.ts` 新增 `SITE_BASE_URL` 环境变量（生产机填正式域名，当前待定）。`/api/sites` 返回 `siteBaseUrl` 与 `siteBaseFrom`：
  - 未配置 → 跟随当前后台访问地址（含 `x-forwarded-proto`），开发机即 `http://127.0.0.1:5199/`，换端口不用改代码；
  - 已配置 → 用环境变量值，面板标注「生产配置 · SITE_BASE_URL」，「打开站点」直接指向正式站点。
- `SiteInfo.url` 改名 `canonicalUrl` 并注明用途，避免以后再被误用。

**本地预览：静态版式（v3.3 纠错）**

- `GET /preview/:siteId/*` 伺服 `sites/<id>/out/`。站点 id 白名单、`..` 拦截、`resolve` 后二次边界校验防目录穿越。
- 起初尝试把 Next.js 产物挂在子路径并改写站内绝对路径，结果踩了一串坑：**HTML 属性改了而内联 RSC flight 数据没改 → React #418 hydration 失败；RSC 预取打到后台根路径 404；统一改写外部 JS 又插坏正则字面量**。
- 最终改为**静态预览**：返回 HTML 时移除全部 `<script>`（含 flight 数据 / JSON-LD），只重写标签属性与内联样式的站内路径；外部 CSS 只重写 `url(/…)`；JS / 图片 / 字体 / txt 一律原样返回。
  - 效果：完整版式与内容、站内导航、图片、样式全部保留，零脚本错误、零 hydration、零预取 404；
  - 代价：客户端交互不工作 —— 面板文案明确写「预览为静态版式，交互以正式站点为准」，交互由正式站点负责。

**v3.4 审核兜底与「草稿 / 已发布」边界（同日追加）**

- 现象：内容区点审核报 `POST /api/sites/demo-saas/modules/review 404`。
- 根因：审核是**服务端写盘**，只能在磁盘 `modules.json` 里找条目；内容区编辑默认只写 localStorage 草稿（`touch()` → `persistDraft()`），新建或刚改过的条目还没 PUT，服务端命中 0 条就返回 404，看着像「接口不存在」。
- 修复：`store.reviewItem()` 在审核前若 `state.dirty` 先 `savePlan()` 落盘；服务端命中 0 条改为 **409 + `code: item_not_found`**，文案「先点保存（⌘S），再审核」。实测未保存草稿点审核 = `PUT 200 → POST 200`，零 404。
- `about:srcdoc` 的 `Blocked script execution`：版面预览 iframe 的 sandbox 只给 `allow-same-origin`（父页面要读 contentDocument 量高度），刻意不给 `allow-scripts`。生成页本就零脚本，再加 `stripExecutable()` 兜底清除知识库正文可能带入的 `<script>` / `on*` / `javascript:`，从源头消掉这条红字。CDP 实测 srcdoc `scripts = 0`、`on* = 0`，console 零错误。
- 「内容区改了，为什么打开站点看不到」：`/preview/<site>/` 首页是 `content/site.ts` 的固定首屏，**不放任何内容区模块**；内容区编排页按自己的 path 落在 `/preview/<site>/solutions/`。内容区「预览」tab 常驻说明条 + 「打开这一页 ↗」直达链接；发布结果面板除「打开站点」外新增「打开 /solutions/」按钮。
- `/api/sites` 新增 `outBuiltAt` / `contentBuiltAt` / `outStale`（比较 `out/index.html` 与 `content/modules.generated.ts` 的 mtime）。本地预览落后时，内容区显示朱红提示「后加的模块要重建后才会出现」。
- `build.ts` 的 `spawn("node")` 改为 `spawn(process.execPath)`：由 nvm / 容器 / systemd 启动的后台，PATH 里未必有 `node`，写死会 ENOENT，发布结果只剩一句「重建失败」。

## 六、组件引用位置标注、页面清单与引用点增删改查（v3.5）

### 6.1 组件被用在了哪些页面的哪些位置

「组件用在哪」以前只有一句数字（`2 处引用`）。数字说有几处，
没说**在哪** —— 于是「改一处会不会漏掉别处」只能靠记忆。

现在组件详情页的「被引用的位置」逐条列出：

```
/solutions · 第 5 块 · 关键数据
/solutions · 第 10 块 · 关键数据
```

- **第 N 块**：模块在页面里的序号（`position`），不是路径
- **模块名**：那一块叫什么
- **条数**：这一处实际显示几条内容

点任意一条 → 跳到内容区、选中那个模块、**闪一下**（朱红描边 2.4 秒）——
「清单说在哪，框说在哪」。

「在内容区标出」按钮：把用到这个组件的**所有**位置在内容区加框高亮
（`.mod--fragmark`，墨蓝描边 + 浅蓝底），跨页面有效 ——
组件页说「有 2 处」，内容区同时框出 2 块。

### 6.2 页面清单（网址入口）

**结论：所有实例的网址不该挂在顶栏第一个按钮（站点切换）下。**

那个按钮的语义是「换站点」，把一堆页面网址塞进去，两个意图混成一个菜单，
站点只有一个时它几乎不用而网址天天要抄。

所以单开一个「页面清单」按钮（在搜索与保存之间），打开是一个抽屉：

| 来源 | 内容 |
|------|------|
| 编排 `modules.json` | 后台管的页面（含模版实例生成的，标「模版生成」） |
| 构建产物 `out/` | 内容包里的固定页（`/about`、`/cases`…，标「内容包」） |

两个来源都要：编排外的固定页不在 `modules.json` 里，只给编排那一半
等于只给了一半地址。新接口 `GET /api/sites/:id/pages` 扫 `out/` 的一级目录
（跳过 `_next` / `_geo` 等下划线目录与 `404`）。

每个页面给：可复制的网址 + 「在新标签打开」。开发机是 `/preview/<site>/…`，
生产机由 `SITE_BASE_URL` 换成正式域名（`site.pageUrl()` 统一算）。

### 6.3 引用点的增删改查

「组件引入到站点后，也应该能增删改查」—— 但组件本体是一份，
改它会波及所有引用点。所以四个动作各有落点，**都不碰片段本体**：

| 动作 | 落点 | 生效范围 |
|------|------|---------|
| 查 | 结构栏直接列出片段本体 + 覆盖的结果 | 这一处 |
| 改 | `overrides.items[].<字段>` | 这一处 |
| 删 | `overrides.items[].hidden` | 这一处 |
| 增 | `PageModule.extraItems[]` | 这一处 |

模块级的标题 / 副标题 / props 也一样：引用型模块写进
`overrides.title` / `overrides.subtitle` / `overrides.props`，
写 `mod.props` 会被展开逻辑忽略（展开用的是片段 props + 覆盖 props）。

### 6.4 「填不进去」的根因：草稿是视图级，不是编辑器局部变量

「单价无法正常编辑」——不是输入框坏了，是**输入的值在一次重绘里被冲掉**。

模板实例编辑器每次重绘都会重建；原来的字段值是编辑器的局部变量，
重绘时重新从服务端取值 —— 用户正打字的内容就没了。

现在草稿提到**视图级**（`drafts: Map<instanceId, {...}>`），
重绘从草稿取，保存成功才删。

同样的坑还有一处：`metrics` 字段的行数组是从草稿里读的，
但当草稿里没有这个字段时，`rows` 是个**临时数组** —— 改它等于改空气。
现在改成 `draftValues.value[field.key] = rows`，数组挂在草稿上。

### 6.5 自检新增「用到却没导入的名字」

踩坑：`app.js` 调了 `drawer()` 却忘了从 `lib/dom.js` 导入 ——
语法完全合法，自检全绿，浏览器里一点就报 `ReferenceError: drawer is not defined`。

`scripts/check-admin-ui.mjs` 现在用 TypeScript 的检查器扫一遍后台的 ES 模块，
只取「找不到这个名字」这一类诊断（2304 / 2552 / 2554）。
实测：故意去掉 `drawer` 的导入 → 自检立刻报出 `app.js:398 Cannot find name 'drawer'`。

### 6.6 验证

- 引用点四件套实测（浏览器 → 服务端 → 磁盘 → 物化）：
  改 → `overrides.items[].value`；隐藏 → `overrides.items[].hidden`；
