# 后台鉴权（Casdoor OIDC）—— 设计与部署

> 2026-11-10 实现。后台（apps/admin）接入 Casdoor 单点登录，
> 密钥验签在本地做（不走 Casdoor 的 introspect —— 它有已知问题，
> SDK 与服务端的参数位置不对称，任何 token 都会判 inactive）。

## 一、登录链路

```
浏览器未登录访问后台
  → 302 到 Casdoor 授权页（带 state 防 CSRF）
  → 用户登录 Casdoor
  → 回跳 /oauth2/callback?code=...&state=...
  → 后台核销 state（一次性，防重放）
  → code 换 access_token（POST /api/login/oauth/access_token）
  → 【本地 JWKS 验签】RS256 + kid 匹配 + iss 双轨 + exp
  → 组织校验（owner/organization 必须是配置的组织）
  → 签发本地会话（HS256，httpOnly cookie，8 小时）
  → 302 回到用户原来想去的页面
```

Casdoor 端点的不对称（既定行为，不是 bug）：

| 用途 | 路径 |
|------|------|
| 授权页（浏览器） | `GET  {external}/login/oauth/authorize` |
| 换 token | `POST {endpoint}/api/login/oauth/access_token` |
| JWKS | `GET  {endpoint}/.well-known/jwks` ← 不是 /api/get_jwks（那个要鉴权） |

## 二、两个 endpoint 为什么要分开

| 变量 | 用途 | 开发机 | 生产 |
|------|------|--------|------|
| `CASDOOR_EXTERNAL_ENDPOINT` | 浏览器跳转（授权页） | Casdoor 公网地址 | 同左 |
| `CASDOOR_ENDPOINT` | 服务端调用（换 token / JWKS） | 同上 | `http://host.docker.internal:3012`（容器内走宿主，避免公网回环 NAT） |

iss 校验是双轨的：两个 endpoint 签发的 token 都合法。

## 三、开启 / 关闭

- **配齐** `CASDOOR_CLIENT_ID` + `CASDOOR_CLIENT_SECRET` + `CASDOOR_REDIRECT_URI` → 鉴权开启
- **缺任一** → 鉴权关闭（无登录直接用），但如果配了一半会在启动时告警
- `/healthz` 恒不鉴权（healthcheck 用）；`/api/*` 未登录回 401 JSON；页面请求 302 去登录

## 四、开发机

- 配置在 `.env.casdoor.local`（**已 gitignore**，不进仓库），`scripts/run-admin.sh` 自动加载
- 删掉该文件即可回到无鉴权开发模式
- Casdoor 应用里「重定向 URLs」须含：`http://127.0.0.1:5105/oauth2/callback`
- 会话密钥：没设 `WB_SESSION_SECRET` 时随机生成 —— 重启后台要重新登录

## 五、生产（457）

1. `/data/secrets/wb.env` 追加七行（模板见 `deploy/bootstrap-457.sh`）：
   ```
   CASDOOR_EXTERNAL_ENDPOINT=<Casdoor 公网地址>
   CASDOOR_ENDPOINT=http://host.docker.internal:3012
   CASDOOR_CLIENT_ID=<生产客户端 ID>
   CASDOOR_CLIENT_SECRET=<生产客户端密钥>
   CASDOOR_ORGANIZATION=zhongkeju
   CASDOOR_REDIRECT_URI=http://<生产公网 IP>:3019/oauth2/callback
   WB_SESSION_SECRET=<openssl rand -hex 32>
   ```
2. Casdoor 应用里「重定向 URLs」登记 `http://<生产公网 IP>:3019/oauth2/callback`
   （3019 的 nginx 已把 `/oauth2/`、`/admin`、`/api/` 反代给容器内的 5105 ——
   见 `deploy/nginx.conf`）
3. 重建镜像（后台代码变了）→ `docker compose pull && up -d`
4. 验证：浏览器开 `http://<生产公网 IP>:3019/admin` → 应跳 Casdoor → 登录后回到后台
5. `127.0.0.1:3020`（SSH 隧道）同样受鉴权保护，登录一次即可

## 六、安全要点

- Casdoor 的 access_token **不落地**：换到后立即本地验签，会话 cookie 是后台自己签的
  HS256，跟 Casdoor 令牌解耦 —— Casdoor 令牌泄露不影响已建立的会话，反之亦然
- 会话 cookie：httpOnly + SameSite=Lax；API 未登录回 401，不做静默降级
- state 一次性核销，5 分钟过期；未知 kid 有 5 分钟负缓存，防打爆 JWKS 端点
- 组织校验：用户 owner/organization 不匹配配置的组织直接 403
- 客户端密钥只从环境变量读，任何情况下不进仓库
