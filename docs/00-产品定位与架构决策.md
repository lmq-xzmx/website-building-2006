## 1. 定位：GEO 产品矩阵的「入口」

本站不是孤立的建站工具，是 GEO 业务矩阵缺失的第四块拼图：

```
website-building（GEO-ready 载体）
      ↓ 内容
GEO-Flow（分发到各平台）
      ↓ 效果
GEO-Monitor（AI 可见性监测）
      ↓ 线索
CRM（转化）
      ↺ 素材沉淀回 GEO-Knowledge
```

**服务对象**：千行万业的客户。借鉴经典企业建站模板，融入 AI 时代新元素。

**数据接口预留（Phase 0 就要留桩）**：
- 询盘表单 → CRM（复用服务间 X-API-Key 体系）
- AI 爬虫访问日志 → GEO-Monitor（哪些 LLM 爬虫来过、抓了什么）

## 2. 核心认知：GEO 时代建站的 5 个本质差异

1. **读者变了**：页面一半的读者是 AI 爬虫（GPTBot / ClaudeBot / PerplexityBot / Bytespider 等），它们抓取是为了**转述**。传统建站优化「人的转化率」，本站优化「AI 转述的准确率」。
2. **流量入口从页面变成句子**：AI 答案引用的是段落而非首页。内容必须原子化——每段自包含、带实体名、带数字、脱离上下文能独立成立。
3. **Schema.org 是给 AI 的 API**：JSON-LD 全覆盖（Organization / Product / FAQPage / Article / LocalBusiness / BreadcrumbList）是 AI 引擎结构化理解站点的第一来源。
4. **FAQ 是 AI 最爱的格式**：问答对直接进答案；HowTo、参数对比表次之。「可引用性」（明确定义、具体数字、对比结构）是 GEO 评分核心信号——**评分思路从 GEO-Knowledge 前置到建站时**。
5. **llms.txt 是新兴标准**：给 LLM 的站点说明书（站点地图+核心摘要+markdown 端点）。成本低、当下即差异化。

## 3. AI 元素二分法（优先级框架）

| 类别 | 内容 | 性质 | 优先级 |
|---|---|---|---|
| **A 类：站点为 AI 而建** | Schema 自动注入、llms.txt 自动生成、FAQ 结构引导、可引用性体检、AI 爬虫识别与分析 | GEO 本体，护城河 | **先行** |
| **B 类：AI 增强建站与体验** | 公司资料→LLM 生成全站文案初稿（接 GEO-Knowledge LLM 能力）、站内语义搜索/AI 客服 | 智能，加分项 | Phase 2 |

**原则：A 做不好，B 再花哨也是给 AI 喂垃圾。**

## 4. 架构决策记录

### 决策 1：技术栈 —— geo-kit 框架无关双栈（2026-11-04）

- **`packages/geo-kit/` 从第一天起框架无关**：纯 TypeScript，不依赖 React。承载 JSON-LD 类型安全生成器、llms.txt 生成、robots/AI 爬虫策略、GEO 体检评分。
- **Next.js 15 模板先行**（App Router + 静态导出），Astro 5 模板后置。
- Astro 触发条件：出现真实需求（如纯内容站客户、极致 Lighthouse 要求）再启动，不预先双写。
- 代价知情：双栈有双倍模板维护面，由「核心逻辑集中在 geo-kit、模板只做壳」控制。

### 决策 2：模板体系 —— 骨架 × 行业内容包（2026-11-04）

- 不是每个行业一个模板。**一个骨架**（页型组件库：Home / Products / Cases / About / Contact / Insights / FAQ）× **N 个行业内容包**（schema 映射、文案结构、术语库、示例内容）。
- 内容包 = TS 配置文件（类型安全、git 可审、可校验），不是数据库后台。
- 第一个模板：**通用企业站**（不特化行业），行业包等真实客户落地再定。

### 决策 3：部署形态 —— 纯静态导出（2026-11-04）

客户站 `next build` 静态导出，扔任意托管（CDN / OSS / NAS / 任意静态服务）。

**理由**：
1. 千行万业规模下边际成本必须趋零（无每站服务器费）；
2. 企业官网内容低频更新，「git push → CI 构建管道 → 部署」覆盖更新需求；
3. GEO 信号全占优：无进程=无宕机（AI 爬虫随时可抓）+ CDN 直出 TTFB/LCP 最优（Core Web Vitals 是 SEO/GEO 共同信号）；
4. B 类能力（AI 客服/搜索/表单）本就是外部 API 调用，不依赖站内服务端——静态缺的是运行时能力，GEO 要的是收录能力，后者静态全满足。

**接受的代价**：
- 内容更新必须过构建管道 → Phase 0 就建 CI 部署流水线；
- `next/image` 需配自定义 loader 或 `unoptimized`；
- 高价值客户若确需服务端（ISR/站内 API），**单站例外升级 Node**，不建第二套监控。

## 5. MVP 路径

| 阶段 | 交付 |
|---|---|
| **Phase 0**（本周） | monorepo 脚手架 + geo-kit 最小核心（JSON-LD 生成 / llms.txt / robots+AI 爬虫策略）+ 通用企业骨架（7 页型）+ CI 部署流水线 |
| **Phase 1** | 第一个真实客户行业样板站 + GEO 体检 v1（评分器思路从 GEO-Knowledge 移植） |
| **Phase 2** | 行业内容包矩阵化 + AI 文案生成管道（接 GEO-Knowledge） |
| **Phase 3** | 询盘→CRM、AI 爬虫日志→Monitor，数据闭环 |
